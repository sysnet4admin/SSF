# 6회차: CI

## 이번 시간의 목표

지금까지 강사가 만든 이미지를 썼다. 이제 내 코드를 push하면 GitHub Actions가 자동으로 내 이미지를 빌드하게 만든다. 그리고 `k8s/`가 내 이미지를 가리키게 바꾼다.

## 사다리에서 지금 위치

앱과 매니페스트는 그대로다. 이미지를 "강사 것"에서 "내 것"으로 바꾼다.

## 핵심 개념

- CI(지속적 통합): 코드를 push하면 자동으로 빌드한다.
- GHCR: GitHub 컨테이너 레지스트리. public으로 두면 인증 없이 pull 된다.
- 자세한 배경은 `decision-guides/ci-cd-tool.md`를 참조한다.

## 진행

### 1. fork

저장소(`sysnet4admin/SSF`)를 본인 계정으로 fork 한다. 화면 우측 상단의 Fork 버튼을 누르면 본인 저장소(`github.com/본인계정/SSF`)가 생긴다.

### 2. push로 빌드 트리거

본인 저장소를 clone 한 뒤 아무 변경이나 push 하면 `.github/workflows/build.yml`이 동작한다. GitHub의 Actions 탭에서 빌드 진행을 확인한다.

### 3. 패키지 public 전환

빌드가 끝나면 GHCR 패키지가 생긴다. 본인 GitHub 프로필 → Packages → 해당 패키지 → Package settings → Change visibility → Public 으로 바꾼다. 이렇게 해야 클러스터가 인증 없이 이미지를 가져온다.

### 4. 내 이미지로 전환

`prompt-guardrails/switch-image.md`를 따라 `k8s/`의 이미지 주소를 본인 계정으로 바꾼다.

## 확인

```bash
kubectl describe pod -l app=backend | grep Image:
```

`Image:`가 본인 계정 주소로 바뀌면 성공이다.

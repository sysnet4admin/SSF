# 7회차: CD

## 이번 시간의 목표

ArgoCD를 설치하고, Git의 `k8s/`를 클러스터와 자동으로 맞춘다(GitOps). `replicas` 한 줄을 바꿔 push하면 클러스터가 따라오는 것을 확인하며 과정을 마무리한다.

## 지금 단계

마지막 단계다. "내가 직접 apply"에서 "Git을 바꾸면 자동 반영"으로 넘어간다.

## 핵심 개념

- CD(지속적 배포): Git이 바뀌면 클러스터가 자동으로 따라온다.
- GitOps: Git이 정답이고, ArgoCD가 클러스터를 그 정답에 맞춘다(reconcile).
- 자세한 배경은 `decision-guides/ci-cd-tool.md`를 참조한다.

## 진행

아래 명령은 모두 저장소 루트(`SSF/`)에서 실행한다.

### 1. ArgoCD 설치

윈도우 터미널의 PowerShell 탭에서 실행한다.

```powershell
.\argocd\install.ps1
```

macOS나 리눅스라면 `.sh`를 쓴다.

```bash
./argocd/install.sh
```

설치가 끝나면 UI 주소와 초기 비밀번호를 화면에 출력한다. 공인 IP 발급이 늦으면 잠시 뒤 다시 실행하면 된다.

### 2. App 등록

`argocd/app.yaml`의 `repoURL`을 본인 fork 저장소로 바꾼 뒤 적용한다. 자세한 절차는 `prompt-guardrails/install-argocd.md`를 참조한다.

```bash
kubectl apply -f argocd/app.yaml
```

`app.yaml`은 어느 저장소의 어느 폴더를 볼지만 정한다. 실제로 배포되는 내용은 그 폴더
(`k8s/`)의 매니페스트에 적힌 값이다. 6회차 마지막에 `k8s/`를 push해 두었다면 본인 이미지가
그대로 뜬다.

> push하지 않았다면 fork의 `k8s/`는 아직 `ghcr.io/sysnet4admin/...`을 가리킨다. ArgoCD가
> 그 값으로 클러스터를 맞추므로 어제 바꿔 둔 본인 이미지가 강사 이미지로 되돌아간다.
> 그런 경우 지금 `k8s/`를 다시 고쳐 push하면 몇 초 뒤 반영된다.

### 3. GitOps 체험

`k8s/backend-deployment.yaml`의 `replicas`를 2에서 4로 바꿔 push 한다.

```bash
git add k8s/backend-deployment.yaml
git commit -m "Scale backend to 4"
git push
```

직접 `kubectl`을 치지 않아도 ArgoCD가 클러스터를 맞춘다.

## 확인

```bash
kubectl get application -n argocd ssf15
kubectl get pods -l app=backend
```

backend Pod가 4개로 늘고, 브라우저 새로고침 시 더 많은 podName이 등장하면 성공이다. 확인은 `result-templates/verify-loadbalancing.md`를 참조한다.

참고: `kubectl scale`로 직접 개수를 바꿔도 잠시 후 Git 값으로 되돌아간다(selfHeal). 기준이 Git으로 넘어갔기 때문이다. 이후 변경은 Git을 고쳐 push하는 것이 기본이다.

## 마무리

이제 코드를 고치고 push하면 빌드(CI)부터 배포(CD)까지 자동으로 이어진다. 앞으로 본인 프로젝트도 이 흐름으로 배포할 수 있다.

## 정리 (선택)

실습을 더 이어가지 않을 때는 비용이 나가지 않게 클러스터를 삭제한다. 무료 체험 크레딧이라도 남겨 두면 계속 소모된다.

```powershell
.\gke\delete-cluster.ps1
```

macOS나 리눅스라면 `./gke/delete-cluster.sh`를 쓴다.

남은 비용 요소가 있는지 AI에게 "이 프로젝트에 비용 나갈 리소스가 남았는지 확인해줘"라고 물어봐도 좋다.

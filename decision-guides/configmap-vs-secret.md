# ConfigMap vs Secret

## 상황

앱에 값을 주입해야 한다. 어떤 값은 공개해도 괜찮고(예: 화면 메시지), 어떤 값은 숨겨야 한다(예: API 키). 쿠버네티스는 이 둘을 다른 그릇에 담는다.

## 쉬운 비유

- ConfigMap: 게시판에 붙이는 공지. 누가 봐도 괜찮은 설정값.
- Secret: 금고에 넣는 열쇠. 코드나 Git에 노출하면 안 되는 값.

## 추천

- 화면 메시지(MESSAGE) 같은 공개 설정: ConfigMap. Git의 `k8s/configmap.yaml`에 둔다.
- API 키 같은 비밀값: Secret. Git에 두지 않는다. 5회차에 클러스터에 직접 생성하고 Deployment는 참조만 한다.

## 비교

| 항목 | ConfigMap | Secret |
|------|-----------|--------|
| 용도 | 비밀 아닌 설정 | 비밀값 |
| Git에 둠 | 둔다(`k8s/`) | 두지 않는다 |
| 생성 시점 | 매니페스트로 함께 | 5회차에 클러스터에 직접 |

## 핵심 개념

- Secret을 Git에 평문으로 올리면 저장소를 보는 모두가 비밀값을 보게 된다. 그래서 Git에는 두지 않는다.
- 현업에서는 sealed-secrets 같은 도구로 암호화해 Git에 두기도 한다. 이 과정에서는 개념만 알아두면 된다.

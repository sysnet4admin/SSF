# CI/CD 도구 선택

## 상황

지금까지는 강사가 만든 이미지를 가져다 썼다. 6회차부터는 내가 코드를 고치면 자동으로 이미지가 만들어지고(CI), 7회차에는 Git을 바꾸면 클러스터가 자동으로 따라오게(CD) 만든다.

## 추천

- CI(빌드): GitHub Actions. 저장소에 YAML 한 파일만 두면 push할 때 자동으로 이미지를 빌드한다. fork 직후 별도 설정 없이 동작한다.
- CD(배포): ArgoCD. Git의 `k8s/`를 계속 바라보다가, 내용이 바뀌면 클러스터를 자동으로 맞춘다(GitOps).

## 비교 (CI)

| 도구 | 특징 | 이 과정 적합도 |
|------|------|----------------|
| GitHub Actions | GitHub 내장, YAML 한 파일, 무료(public) | 높음 |
| Cloud Build | GCP 네이티브 | 트리거 설정 추가 필요 |
| Jenkins | 자체 서버 운영 | 학습 환경엔 과함 |

## 비교 (CD)

| 도구 | 특징 | 이 과정 적합도 |
|------|------|----------------|
| ArgoCD | Git을 기준으로 자동 동기화(GitOps), UI 제공 | 높음 |
| kubectl 수동 apply | 직접 명령 실행 | 자동화 아님 |

## 핵심 개념

- GitOps: Git이 "정답"이고, 클러스터가 그 정답을 따라가게 만드는 방식. 무엇을 배포했는지가 Git 기록에 그대로 남는다.
- 이 과정에서는 GHCR(GitHub 컨테이너 레지스트리)을 public으로 써서 인증이나 pull secret 없이 바로 동작하게 한다.
